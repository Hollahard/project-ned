# Owned WebSocket diagnostic checkpoint — 2026-10-08

The new [owned-ws component](../../hermes-native/services/owned-ws/README.md) proves bounded local WebSocket exchanges over a socket whose server belongs to the caller's private Windows Job. It reuses the existing HTTP socket-ownership check and a pinned protocol implementation. It starts no Hermes backend, exposes no renderer connection, and makes no gateway-ready claim.

## What was implemented

Rust connects once to explicit IPv4 loopback, resolves the exact reversed established tuple through the Windows TCP owner table, and checks the observed process through a query-only handle against the private Job before constructing or sending upgrade/credential bytes. That same TCP stream goes to the supplied-stream protocol client. No DNS, proxy, redirect, second connection, port-only ownership check or PID-based termination is involved.

The fixed route is `/api/ws`, with the existing Hermes query-token spelling generated only inside Rust. Tokens are bounded ASCII unreserved strings. Upgrade responses reject unsolicited extensions/subprotocols, duplicate critical headers and excessive headers. Public operations support bounded text/binary messages, fragmentation, control frames and a verified close exchange. Errors are fixed codes; data-bearing types have no Debug/serialization implementation. Protocol or deadline failure aborts the stream without retrying uncertain writes.

One absolute deadline covers connect/ownership/upgrade; each send/read and the complete close exchange has a separate finite deadline. The defaults are five, fifteen and two seconds, respectively. Message size is at most 1 MiB, incoming frames default to 256 KiB, headers to 16 KiB, and wire traffic is at most 4 MiB per operation. A stream wrapper carries the same deadline through fragmented reads and automatic pong/close writes and checks owner membership before each I/O. It preserves any first frame coalesced with the upgrade response.

A successful close receipt means the protocol exchange and TCP close were observed within the owner/deadline checks. It does not mean the backend process stopped. Fixture owners separately prove root exit, both output EOFs and empty Job membership. Kernel queries are synchronous; these limits are not hard real-time guarantees or an OS sandbox.

The shared HTTP change only factors its existing verified connect into `connect_owned` and exposes a query-only observed peer identity. Its original request deadline and fixed-route/framing checks remain intact. The [exact source diff](implementation-evidence/owned-ws-http-source.diff) and [42-file integration receipt](implementation-evidence/owned-ws-source-receipt.json) record the boundary. Resource-host source and the HTTP lockfile are unchanged.

## Required next step: a live event loop

This API is intentionally a **finite diagnostic transport**. Its blocking `read(&mut self)` prevents sends while waiting, and a read deadline aborts even an otherwise healthy idle socket. The retained channel's `gateway.ping` is a JSON-RPC heartbeat every fifteen seconds with a forty-five-second peer deadline; WebSocket Ping/Pong handling does not satisfy that contract. Raising the read timeout cannot make a single blocked actor dispatch queued requests.

Before native renderer or real gateway integration, implement a cancellation-aware event loop that can receive and send independently, with bounded queues, preserved ordering, owner/document generation fences, and distinct idle-wait versus partial-message deadlines. Verify idle longevity, queued sends while idle, heartbeat/reconnect behavior and shutdown with pending I/O against the unchanged client. Do not solve this by replacing the retained client or reporting a placeholder successful connection.

The [backend integration plan](NEXT-BACKEND-INTEGRATION.md) and [socket acceptance plan](NATIVE-SOCKET-TEST-PLAN.md) now record this gate before managed Hermes startup, real session RPCs and a bounded agent conversation. Vector memory, inference/context profiling, ExLlamaV2 qualification, Gaming Mode/fallback/hibernation, complete desktop parity and installer packaging remain open. The recorded Qwen3 EXL3 proof is separate and its prepared directory is consumed; no GPU operation ran for this transport checkpoint.
