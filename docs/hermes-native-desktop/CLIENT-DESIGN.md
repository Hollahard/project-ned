# Retained client and native socket actor contract

**Design only — 8 October 2026.** This refines [the backend plan](NEXT-BACKEND-INTEGRATION.md) and [socket acceptance plan](NATIVE-SOCKET-TEST-PLAN.md) against Hermes `649d6c0391029f35959cfbc240eb3534a6667cf5`, with Project Ned at `dfb63a7`. It does not implement a renderer socket, launch Hermes or certify production chat. Exact source hashes and anchor lines are in [CLIENT-SOURCE-MANIFEST.json](CLIENT-SOURCE-MANIFEST.json). No upstream or worktree source was changed or imported.

The companion [Rust actor design](RUST-DESIGN.md) specifies ownership, bounded scheduling and the prerequisite parser-progress API.

## 1. Actual retained surface and construction seam

The shared [client options](https://github.com/NousResearch/hermes-agent/blob/649d6c0391029f35959cfbc240eb3534a6667cf5/apps/shared/src/json-rpc-gateway.ts#L16) alias `WebSocketLike` to the entire browser `WebSocket` type. Actual gateway execution uses only `addEventListener`, `removeEventListener`, `readyState`, string `send` and argument-free `close`; it compares against the global browser `WebSocket.OPEN` constant. It does not consult `bufferedAmount`, set `binaryType` or construct sibling sockets through its factory. The shared request channel already emits serialized JSON strings.

The least invasive seam is a reviewed build-time transform of **only** [desktop `api/client.ts`'s `HermesGateway` constructor](https://github.com/NousResearch/hermes-agent/blob/649d6c0391029f35959cfbc240eb3534a6667cf5/apps/desktop/src/api/client.ts#L31): add one explicit native-factory import and one `socketFactory` option to its existing `super({...})`. Existing primary and secondary `new HermesGateway()` call sites then retain their options and behavior. Preserve both shared JSON-RPC modules byte-for-byte. Gate the transformation by whole-file input hash, exact constructor/import match counts and reviewed output hash; record it as an adaptation, never as unchanged generated bytes.

Project Ned's existing `apps/desktop-ui/scripts/build.mjs` already owns the wrapper Vite plugin. Add the narrowly targeted transform there, a new `src/native-gateway-socket.ts` implementation, and explicit transport types/lifecycle wiring in `src/host-adapter.ts` and `src/entry.ts`. The shell counterparts are `apps/desktop-shell/src/transport.js`, a dedicated new socket bridge module, command registration in `src/main.rs` and the finite capability declaration. Native I/O belongs in a dedicated actor/owner, not the profile/catalog workers. Do not replace `window.WebSocket`, monkeypatch shared prototypes or alias all of `@hermes/shared`. An isolated native fixture can first construct the unchanged client with an explicit factory without exposing a production `getConnection`.

## 2. Synchronous object, asynchronous owner

| Contract | Required behavior and reason |
| --- | --- |
| Factory return | Return one non-null socket object synchronously in CONNECTING state, even when the native open later fails. Defer events until registration is possible. A thrown factory leaves upstream in `connecting`; a nullish return invokes its browser-network fallback at [line 212](https://github.com/NousResearch/hermes-agent/blob/649d6c0391029f35959cfbc240eb3534a6667cf5/apps/shared/src/json-rpc-gateway.ts#L210). Reject unknown opaque handles through deferred failure; never dial a renderer-supplied URL. |
| Registration | Implement real EventTarget ordering, duplicate-listener identity, removal and `{once:true}`; honor abortable registrations if exposing the complete DOM type. Upstream installs permanent message/close listeners, then temporary open/error/close listeners, and removes the latter when settled. No error, ready message or close may be lost during the native subscription handshake. |
| Open ordering | Buffer any post-upgrade bytes until the renderer has a registered delivery channel. Set OPEN before dispatching `open`, then release complete messages in wire order. The `open` handler attaches the JSON-RPC channel and starts replay before notifying open subscribers. A 101 plus first ready frame in one TCP read must follow the same order. |
| Failure and close | Set CLOSED before one terminal close notification. Pre-open failure settles connect once; post-open failure must include close, since upstream removes its temporary error listener after open. Do not report a rejected HTTP upgrade as a received 4401/4403 WebSocket close. A late failure cannot close a replacement socket. Local native errors use fixed messages, never raw paths, tokens or child text. |
| Send admission | `send` returns `void`, never a Promise. Reserve finite message and UTF-8-byte credits synchronously before native invocation. Rust rechecks admission, owner/document/socket generation, sequence and bytes before scheduling work. A native invoke failure after local admission is an uncertain transport outcome: close the generation, reject its pending RPCs and never automatically resend. |
| Bidirectional bounds | Bound the JS outbox, native send queue, receive assembly, native-to-WebView outbox and outstanding delivery acknowledgments independently. Reserve terminal error/close delivery outside the data-credit lane. Scheduling unlimited events/evals after draining a bounded Rust queue is still unbounded. Acknowledgments release credits; they confer no authority. |
| Disposal | `close`, full navigation, owner retirement and subscription failure fence new work immediately. Cancellation can reach an independently published owner during open/read/write; it cannot wait behind a held I/O lock. Apply window/origin/document/socket checks to send, ack and close as well as open. Hash navigation alone preserves the document owner. |

Tauri command validation bounds admitted application work; it does not by itself bound allocations incurred before the command handler deserializes a malicious invoke flood. Qualify concurrent-invoke behavior separately. Native delivery needs an explicitly scoped channel; a renderer-readable identifier without native owner checks is not a capability boundary.

Also cap open sockets and pending creates per document and per backend, total registry bytes, and retired-handle retention. Per-socket queue limits cannot prevent exhaustion by creating many sockets. Retired generations must become rejectable without an indefinitely growing tombstone map.

A candidate versioned command boundary is `create(endpointHandle)` → opaque `socketHandle`, followed by `activate(socketHandle)` only after delivery listeners are installed; `send(socketHandle, sequence, text)`, `ack(socketHandle, deliveredSequence)` and `close(socketHandle, code?, reason?)` all return typed results. Native scope supplies the actual window/document owner, never a trusted renderer-provided label. Every event carries socket generation and monotonic event sequence plus exactly one typed open/message/error/close payload. Create publishes cancellation state before blocking work; activation prevents first-event races. A send receipt distinguishes admission from completed socket write, and neither means RPC completion. This DTO is proposed, not an existing command API.

**Browser conformance versus gateway subset.** Browser ready states are 0/1/2/3. The complete type also includes event-handler properties, URL, protocol/extensions, binaryType, bufferedAmount and binary/Blob send. Standard `send` throws while CONNECTING, silently discards during CLOSING/CLOSED and closes on buffer exhaustion. `close` accepts omitted code, 1000 or 3000–4999; reasons are limited to 123 UTF-8 bytes. Code 1006 describes local abnormal closure and is never sent on the wire. `bufferedAmount` counts queued application bytes, not peer receipt or RPC completion. These are [WHATWG requirements](https://websockets.spec.whatwg.org/#the-websocket-interface), not behavior inferred from the TypeScript alias.

For a gateway-only prototype, explicitly document and test any stricter non-open/oversize rejection or unsupported binary send. Do not claim full browser conformance or solve a type error with an unchecked cast. Prefer implementing the public type with tested behavior before routing audio/display consumers through it. `bufferedAmount` must track actual locally/native queued bytes and decrease on verified write completion, not merely successful IPC admission. For full Blob/buffer support, reserve size and sequence before asynchronous conversion so conversion cannot reorder sends. The retained JSON serializer escapes lone surrogates; a general DOM string adapter must separately qualify USVString normalization. Use the bytes actually encoded for admission, not JavaScript `.length`.

## 3. Framing, liveness and replay

**One JSON object per complete WebSocket text message.** [Server token coalescing](https://github.com/NousResearch/hermes-agent/blob/649d6c0391029f35959cfbc240eb3534a6667cf5/tui_gateway/ws.py#L195) schedules a batch but loops over `send_text` separately for each serialized object. [Shared `handleFrame`](https://github.com/NousResearch/hermes-agent/blob/649d6c0391029f35959cfbc240eb3534a6667cf5/apps/shared/src/json-rpc-channel.ts#L435) calls `JSON.parse` once. Never join several notifications with newlines or a JSON array. Reassemble RFC fragments before a MessageEvent; several messages in one TCP read remain several MessageEvents. The gateway decoder accepts strings, ArrayBuffer and views; it ignores Blob. Native JSON-RPC should therefore deliver text strings, leaving binary streams to separately qualified routes.

The shared heartbeat starts only when real `gateway.ready` advertises it. Its interval/deadline are **15/45 seconds**, with desktop `any-inbound` liveness for successfully parsed objects and bounded outstanding ping IDs. It measures against pings actually sent, accounting for hidden-WebView timer throttling. WebSocket Ping/Pong is separate and must not be converted into `gateway.ping` results or synthetic JSON-RPC traffic. A healthy idle connection must outlive a diagnostic read timeout; use a cancellable duplex actor, finite partial-frame/message deadlines, and distinct connect/upgrade/write/close deadlines. A blocking read must not starve outbound RPCs or heartbeat sends.

The current `owned-ws` diagnostic defaults are 1 MiB/message, 256 KiB/incoming frame, 16 KiB/upgrade header and 4 MiB/wire operation, with 5-second connect, 15-second operation and 2-second close budgets. It has no application queue, and its blocking read timeout would close a healthy idle gateway. These are verified diagnostic constraints, not production actor defaults. The companion Rust design's finite queues are proposed qualification limits; neither set proves large-history compatibility.

Keep clients scoped to `(connection, profile, backend generation)` and sockets to a document/socket generation. Never retarget a channel to another owner: a delayed server-request response uses that channel's current transport. Reconnect preserves upstream epoch/sequence/replay logic; native code does not replay requests. AbortSignal only cancels local pending calls, while agent interruption is an explicit protocol operation. A replay barrier permits history reads after success, truncation, unsupported replay or restart; it does not certify full history. Event subscriptions require explicit disposal even after `close`.

The socket actor borrows the actual backend owner's identity/Job for admission; it does not become another process supervisor. Closing or replacing one socket retires that socket, not a backend still used by another socket or window. Only the backend lifecycle owner decides when to retire the process group and verifies its process/pipe cleanup. Socket close and backend retirement need distinct receipts and tests.

Do not carry the CPU worker's 64 KiB frame limit into chat. [Session history](https://github.com/NousResearch/hermes-agent/blob/649d6c0391029f35959cfbc240eb3534a6667cf5/tui_gateway/contracts/sessions.py#L487) has no pagination argument and returns the whole transcript; resume may include messages/open requests, and replay returns event lists. Choose and expose host-owned limits only after measuring synthetic long histories, tool output and attachment cases. Boundary failures must be explicit, never truncate JSON or omit transcript rows. Transport queue limits also do not bound the shared client's `replayHold` array or downstream UI stores; qualification must measure those while replay is delayed. Splitting one RPC response into new application messages requires a reviewed protocol change, not a transport optimization.

## 4. Descriptor and direct-URL inventory

`HermesConnection` [requires](https://github.com/NousResearch/hermes-agent/blob/649d6c0391029f35959cfbc240eb3534a6667cf5/apps/desktop/src/global.d.ts#L971) `baseUrl`, `token`, `wsUrl`, logs and window fields. Keep credentials inside the host. The gateway URL must be syntactically `ws:`/`wss:` for the unchanged validator, but its opaque handle must name an actual host-issued owner/endpoint grant. Non-OAuth resolution [falls back to `conn.wsUrl`](https://github.com/NousResearch/hermes-agent/blob/649d6c0391029f35959cfbc240eb3534a6667cf5/apps/shared/src/websocket-url.ts#L79) if minting fails: stale descriptor handles must fail closed at native admission. OAuth/registry flags must describe actual routing, not be invented to suppress consumers. A safe descriptor projection remains an integration gate, not permission to return fake readiness.

Direct WebSocket constructors still need separate adapters. Do not loosen browser CSP/network permissions to make opaque URLs accidentally usable.

## 5. Startup and acceptance boundary

[Actual boot](https://github.com/NousResearch/hermes-agent/blob/649d6c0391029f35959cfbc240eb3534a6667cf5/apps/desktop/src/app/gateway/hooks/use-gateway-boot.ts#L1456) resolves a scoped descriptor with a bounded host call, publishes it, seeds workspace cwd, mints a URL, connects, adopts the primary profile and concurrently refreshes cwd/config/sessions before declaring desktop boot complete. Connection open alone is therefore insufficient. Config fetch/defaults, active-profile reads and sidebar session requests are concrete initial REST dependencies; the sidebar uses `/api/profiles/sessions/sidebar` with legacy fallback. Config refresh can also start voice-status reads, and sidebar maintenance fetches cron jobs. These calls need genuine managed handlers or clearly scoped unavailability, not fabricated empty successful data.

The hook also subscribes to boot progress, backend exit, connection-applied and optional power/window/pool events. It uses RPC `ping` for liveness probes, distinct from automatic `gateway.ping`; optional startup metrics call `shared_metrics.startup_latency` only when a native claim exists. Startup REST has a 60-second per-call override; gateway defaults are 30 seconds, and prompt acknowledgment may allow 1,800 seconds. Do not set one global actor lifetime timer equal to these application deadlines. Validate the actual startup burst in a retained native fixture; this is a minimum dependency inventory, not a complete all-plugin startup audit.

Before a production descriptor is enabled: rerun the unchanged 19-test client harness; add native factory/no-fallback, listener ordering, simultaneous open+ready, string-byte accounting, queued-send failure, peer/owner cancellation and bounded delivery tests; then qualify a real retained route, real handlers and the startup REST burst. Separately test long history/replay and every newly supported bypass family. Default production backend-unavailable behavior remains until these gates pass. None of this upgrades a diagnostic owned WebSocket proof into full desktop, audio, display, agent or inference parity.
