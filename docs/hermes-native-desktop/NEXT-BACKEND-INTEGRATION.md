# Next backend integration: owned Hermes conversations

**Proposed work, not completed readiness.** This plan was reviewed on 8 October 2026 against Hermes `649d6c0391029f35959cfbc240eb3534a6667cf5` and Project Ned checkpoint `9641910`. It preserves Hermes's Python session/agent handlers and shared TypeScript client while moving process and socket ownership into Rust. Research for this document did not launch Hermes, import its modules, read dotenv files, or access user conversation state.

## Starting point and next deliverable

The [owned backend checkpoint](OWNED-BACKEND-CHECKPOINT.md) proves twelve real HTTP diagnostic checks for retained configuration/session-list handlers, exact established-socket ownership before credentials, and cleanup after intentional failure. It excludes the gateway and stock startup. The [gateway harness](../../hermes-native/tests/gateway/README.md) has nineteen tests of the unchanged shared client; those fixtures do not qualify all 252 declared RPC methods or Python handler semantics. The profile service, metadata inspector and separate [Qwen3 runtime observation](QWEN3-RUNTIME-CHECKPOINT.md) do not fill that gap.

The next deliverable is one opt-in local backend generation, one explicitly owned Hermes home and workspace, and real session RPCs followed by a bounded conversation. Begin with fresh synthetic state. Keep the production renderer's backend-unavailable state until its actual startup requests and connection lifecycle work. A passing subset must remain labeled as a subset; no successful placeholder connection or disabled-feature success responses.

For every adaptation, require the pinned commit, full input SHA-256, exact symbol/call-site match and occurrence count, reviewed output hash, and an explicit manifest entry. Hash mismatch stops preparation. Leave session, prompt, replay, contract and shared-channel implementations byte-identical.

**Automatic-services policy:** prohibit machine-wide orphan/process sweeps, rendezvous/token files, update/install paths, browser opening, guest-account minting and stock local-runtime autostart. Start with cron, hosted-room recovery, messaging, external memory providers, shell hooks, plugin activation and MCP discovery explicitly unconfigured. Restore each behind its own scoped ownership/acceptance gate; this is experimental scope, not silent removal from the parity target. Permit only audited schema/transcript writes and necessary session maintenance inside the new home. The database orphan-row sweep is distinct from killing unrelated processes; [its existing configuration gate](https://github.com/NousResearch/hermes-agent/blob/649d6c0391029f35959cfbc240eb3534a6667cf5/tui_gateway/session_reaper.py#L502) can disable it initially. Audit watcher paths before advertising `change_events: true`; never announce capabilities whose producers were suppressed.

## Owned WebSocket and renderer boundary

Add a separate `owned-ws` transport. The current finite HTTP client requires response EOF and rejects upgrade responses; it is not a WebSocket transport. Reuse its exact established IPv4 tuple → query-only PID handle → private Job membership check. Perform that check on the connected stream **before any upgrade headers or credential bytes**, then give that same stream to a pinned WebSocket implementation. A URL convenience helper must not reconnect. Reject redirects, unexpected upgrade/subprotocol/extension responses, oversized frames and queue overflow; define total connect/upgrade deadlines and bounded close/drain behavior. Preserve text message boundaries and newline-coalesced JSON-RPC notifications.

Rust mints a per-generation credential and supplies it only through the child environment. [Unchanged local WS authentication](https://github.com/NousResearch/hermes-agent/blob/649d6c0391029f35959cfbc240eb3534a6667cf5/hermes_cli/web_server_chat.py#L250) expects `?token=`; a Bearer header alone does not satisfy it. The minimal first slice may construct that authenticated target exclusively inside Rust after ownership verification. Disable URL/access-log persistence and prove credential-canary absence in reports, child-owned files and browser state. Server auth/host/origin gates must reject **before** `handle_ws` accepts. This legacy path has no dashboard user identity; privileged identity-dependent RPCs remain unavailable until separately qualified.

Expose only window/document-bound opaque connection/socket handles to the renderer. Audit the required `HermesConnection.token/baseUrl/wsUrl` projection and every direct URL consumer: no credential-bearing URL or token may reach WebView. A syntactically valid opaque WS URL can feed the factory only if it resolves to a native-issued owner handle; unknown values must reject without browser-network fallback. The adapter must implement the existing client's event ordering, `readyState`, `send`, `close` and listener disposal. `getConnection` resolves only after authenticated verification of the owned backend, independently of dashboard user identity; socket `open` means successful upgrade, while real `gateway.ready`, negotiation and initial RPC results establish subsequent readiness. Do not merge these milestones.

Keep a distinct client/channel for `(connection, profile, backend generation)` and a separate socket generation for reconnect. Fence new work before shutdown/navigation; invalidate handles, reject pending calls, request cooperative turn/session shutdown and bounded transcript flush, then terminate only the private Job if needed. Verify root exit, all descendants gone and pipe EOF. Forced cleanup is not proof that every transcript write was durable. The profile worker, catalog inspector and inference runtime keep their separate owners.

## Sequential acceptance gates

1. **Real RPC without agent construction.** Use the retained `/api/ws` route, real `gateway.ready`, `client.capabilities`, `gateway.ping`, `session.list`, lazy `session.resume`, `session.history` and `session.events.since` against seeded synthetic state. Confirm no agent/provider/tool construction, no dotenv reads or external network, and strict generated contracts. Test wrong/missing credentials, host/origin refusal, an unrelated listener receiving zero application bytes, conflicting readiness, malformed/oversized frames, slow peers, child crashes and shutdown during connection. Audit lazy resume's actual side effects rather than relying on its name. Do **not** include `session.create` yet: [it schedules agent construction immediately](https://github.com/NousResearch/hermes-agent/blob/649d6c0391029f35959cfbc240eb3534a6667cf5/tui_gateway/methods_session.py#L478).
2. **Real conversation semantics.** After auditing agent construction, provider selection and shell-hook/tool policy, exercise unchanged `session.create`/`prompt.submit` through `AIAgent` using an explicitly owned deterministic provider fixture. Do not replace gateway responses or enable the synthetic-agent shortcut. Require a user row, streaming deltas, terminal `message.complete`, authoritative history, restart/resume persistence and error rendering. Creation retry uses its existing idempotency key; never automatically replay an uncertain `prompt.submit`. Acknowledgment is not turn completion. Test `session.interrupt` and terminal outcome; local AbortSignal alone sends no cancellation frame. Exercise real server-request/open-request cancellation and owner isolation with a controlled harmless fixture.
3. **Retained desktop and real model gate.** Run the unchanged shared client and real retained Chat/History route through the native factory, covering startup REST/RPC requests, send/stop, reconnect and restart. Preserve replay epoch/sequence handling, `open_requests`, truncation fallback and authoritative history refresh; replay success is not complete-history certification, and live events are not globally deduplicated by the shared client. Then perform one bounded real-model chat turn through the separately owned inference endpoint. Existing completions-only model proofs do not qualify chat templates, tool calling, streaming chat format or auxiliary model calls. Keep load/unload/profile APIs outside the Hermes gateway integration.

For each gate, use a fresh receipt and synthetic home, archive only sanitized evidence, and rerun the nineteen client tests plus the relevant native/handler tests. Measure preserved input files and their hashes against the [retention baseline](retention-baseline.json), the candidate's exact Python inventory, and the build adapter manifest before and after execution. The existing 2,986-file baseline is a source-preservation measure, not a claim that every feature works. Source caches/native import shadows, permitted dependencies, filesystem grants and all spawned children require explicit inventories. Python audit hooks are tripwires, not an OS sandbox.
